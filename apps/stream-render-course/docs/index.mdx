# 从第一段文字，到一个完整的聊天项目

先看见效果，再理解原因，然后亲手实现。一路使用同一个聊天场景，学会网络数据怎么来、界面为什么会卡、怎样证明优化没有丢字。

[开始 5 分钟体验 →](/learn/00-quick-start) · [安装与运行](/setup) · <LabLink path="/project">先看看最终项目</LabLink>

## 这门课适合谁

会基本 JavaScript，但没写过流式请求的同学。前几课不要求你认识 SSE、ReadableStream 或 React 性能分析。

不熟悉函数、数组或 async / await？先用 [预备知识](/basics) 的短代码热身。React 和 TypeScript 只在需要时解释。

## 学习路线

| 阶段             | 你会解决的问题                   | 完成后能做什么                     |
| ---------------- | -------------------------------- | ---------------------------------- |
| 00–03 先做出来   | 等待和分段显示有什么区别？       | 写出可回放的最小聊天               |
| 04–07 理解网络   | 中文为什么乱码？半截消息怎么办？ | 从真实 HTTP 响应中读出正文         |
| 08–10 可靠与流畅 | 停止后还更新？每个字都重算？     | 取消请求并合并显示更新             |
| 11–14 渲染进阶   | Markdown 闪烁，长回答越来越慢？  | 理解预览修补、稳定块和重型任务     |
| 15–18 组装项目   | 如何把这些能力接起来？           | 完整 Mini Chat、故障排查与性能验证 |

**推荐路线：** 首次学习先完成 00–10，再走 15、16、18 做出完整项目。11–14、17 是性能进阶，完成项目后再回来深入。你不需要实现三种服务商协议才能写出第一版聊天。

## 每次只走一小步

1. 先在课内实验观察现象，写下预测。
2. 打开文中指定文件，理解输入和预期输出。
3. 完成一处练习或有明确预期的修改。
4. 运行本课命令，核对结果。
5. 对照参考实现，解释为什么成立，再进入下一课。

01–06 与 10 是带 TODO 的独立练习；其他章节是源码实验和项目组装，文中会明确区分。每课练习自带上一阶段的参考能力，不会自动读取你在上一课写的代码。
