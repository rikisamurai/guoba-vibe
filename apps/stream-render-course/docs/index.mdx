# 从“等完整答案”开始，亲手造出 Streaming Chat

这不是 API 名词手册，也不是把完成品拆成 18 篇介绍。你会一直维护**同一个 mini-chat**：先渲染一条完整回复，再加入可重复播放、增量 UTF-8、SSE、provider adapter，最后才讨论调度、Markdown 与性能。

每一课只增加一个能力，`starter(N) = solution(N-1)`。先复现失败，再填一个 TODO，用同一组 contract test 证明这一步真的成立。

## 你最终会做出什么

```text
Response bytes
  → incremental UTF-8
  → WHATWG SSE
  → provider delta
  → raw / visible state
  → scheduled React commits
  → safe rich-text rendering
```

最终项目不是一个漂亮但解释不清的黑盒：每层都有 fixture、可控时钟、失败示例和可观察指标。你能从 Network 中一个被切断的 emoji，一路解释到 React 为什么少 commit 一次。

## 开始前只需要这些

- Node.js `>= 24`
- pnpm `11.3.0`（仓库的 `packageManager` 会固定版本）
- 会 TypeScript、React state、Promise 和基础 HTTP

在 **guoba-vibe 仓库根目录**运行：

```bash
node --version
corepack pnpm --version
pnpm install
pnpm dev:stream-render
```

看到下面两行就说明入口正确：

```text
stream-render-course  Local: http://localhost:5173/
stream-render-lab     Local: http://localhost:5174/
```

打开 Course `http://localhost:5173/` 阅读；打开 Lab `http://localhost:5174/` 做实验。若端口被占用，启动脚本会直接报告冲突端口；确认并停止旧进程，或分别指定 `STREAM_RENDER_COURSE_PORT`、`STREAM_RENDER_LAB_PORT` 后启动。

## 你会一直编辑的目录

```text
apps/stream-render-lab/workshop/mini-chat/
├── 01-static-chat/
├── 02-replay-clock/
├── 03-m0-baseline/
├── 04-utf8/
├── 05-sse/
└── 06-chat-completions/
```

每层都有 `exercise/`、`solution/`、`fixture.ts` 和 `contract.ts`。只改 `exercise/`；卡住时先看提示，再看 solution diff，不要一上来复制答案。

## 第一阶段：六次连续增量

| 课  | 只新增的能力             | 完成后的证据                    |
| --- | ------------------------ | ------------------------------- |
| 01  | 完整字符串回复           | 一条 user + assistant 消息      |
| 02  | Replay + VirtualClock    | 时间不前进，文本就不前进        |
| 03  | raw / visible            | 到达事实与屏幕状态分别记录      |
| 04  | 增量 UTF-8               | 任意 byte split 都不乱码        |
| 05  | WHATWG SSE               | 字段、空行和 EOF 语义正确       |
| 06  | Chat Completions adapter | wire event 变成 mini-chat delta |

## 每课固定循环

1. 运行 exercise，确认它以文档写明的方式失败。
2. 在 Browser checkpoint 里先写下预测。
3. 只填本课的 TODO，再运行同一个测试。
4. 对照 solution diff，解释 invariant 与 trade-off。
5. 通过 checkpoint 后再进入下一课。
