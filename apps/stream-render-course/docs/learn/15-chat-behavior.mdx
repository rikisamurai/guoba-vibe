# 正文正确了，聊天也要好用

**类型：项目交互验收。** 打开 `apps/stream-render-lab/src/learn-project/project-page.tsx`。

## 第一步：从空状态开始

打开 <LabLink path="/project">Mini Chat</LabLink>，看到空状态提示后发送一条消息。检查用户输入立刻出现，助手区域显示等待，而不是整页空白。

## 第二步：避免重复发送

接收期间发送按钮不可用，停止按钮可用。按 Enter 也不应绕过忙碌状态；表单的 submit 处理需要和按钮一致。

把输入清空，发送应禁用。恢复一段文字再发送。空输入不是网络错误，不必发给服务端再处理。

## 第三步：保留已有对话

连续完成两轮。后一轮增长不应擦掉前一轮；停止只影响当前轮。重试追加一条新尝试，让失败记录仍可查看。

当前教学项目只在内存里保存历史，刷新即清空。持久化和登录不属于这门流式课程的必做范围。

## 第四步：检查可访问性与阅读行为

用 Tab 移动到输入、发送和停止，按 Enter 操作。状态通过 role=status 宣告，不要每收到一个字都强制播报整段正文。

教学项目不强制滚动，避免抢走正在阅读历史消息的用户。若要添加跟随滚动，只在用户接近底部时跟随；用户向上滚动后停止自动跳转。

## 第五步：做一次可见的修改

临时把空状态提示换成你能理解的引导语，检查桌面和手机宽度下仍能读完整。不要同时修改请求逻辑。确认后恢复课程示例文案，避免练习改动混入后续代码。

```bash
pnpm --filter stream-render-lab exec vitest run src/learn-project/read-answer.test.ts
```

这条命令只检查数据链，不代替上面的键盘与交互验收。
