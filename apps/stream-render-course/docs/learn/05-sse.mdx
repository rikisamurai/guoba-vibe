错误实现只认识 LF 双换行。下面一个事件故意混用换行并跨 chunk：

```text

id: 42\r
event: message\n

```

正确结果的 `data` 是 `first\nsecond`；comment 不进入事件。

## 最小原理：chunk → line → field → event

```text
text chunk
  → line scanner        识别 CR / LF / CRLF
  → field accumulator   处理 data / event / id / retry
  → blank line          派发一个 event
```

解析过程保存当前 event 字段与上一条有效 `id`；line scanner 则统一处理三种换行。transport chunk 在这里没有语义。

### 六条必须写进测试的规则

1. 开头的 UTF-8 BOM 只忽略一次。
2. CR、LF、CRLF 都结束一行，CRLF 跨 chunk 仍算一次。
3. 多行 `data` 用 `\n` 连接，派发前去掉最后追加的换行。
4. `:` 开头是 comment；未知 field 忽略。
5. `retry` 只有全十进制数字才更新；`id` 含 NUL 时忽略。
6. **EOF 不是空行**：未被空行派发的残留 event 丢弃。

## Solution diff

```diff
-return { events: [], lastEventId: '' }
+const events = []
+const buffer = { data: '', type: '', lastEventId: '' }
+for (const line of completeLines(decodeUtf8Chunks(chunks))) {
+  if (line === '') dispatch(buffer, events)
+  else if (!line.startsWith(':')) applyField(line, buffer)
+}
+return {
+  events,
+  lastEventId: buffer.lastEventId,
+  ...(buffer.retryMs === undefined ? {} : { retryMs: buffer.retryMs }),
+}
```

## Checkpoint：parser 不依赖 transport 分块

- [ ] same bytes 的 every-byte 与整块输入产生相同 events。
- [ ] 多行 data 保留中间 `\n`。
- [ ] comment 不派发，EOF residue 不派发。
- [ ] CRLF 在 `\r | \n` 之间切开仍正确。

**Invariant：** parser 输出只由完整 SSE lines 与空行决定，与 byte/text chunk partition 无关。

**Trade-off：** 状态机比 `split` 多保存少量状态，却能准确区分完整事件与截断残留。

**退化条件：** 只有 LF、单行 data 的理想 fixture 会让错误实现看似正确，所以不能作为唯一测试。

## 常见错误

| 错误                   | 后果                              |
| ---------------------- | --------------------------------- |
| `trim()` 整行          | 改掉 data 中有意义的尾空格        |
| EOF 自动 dispatch      | 把截断 payload 当成完整事件       |
| parser 内 `JSON.parse` | 协议 framing 与 provider 语义耦合 |
| CR 后立即发空行        | 跨 chunk CRLF 可能被算两次        |
