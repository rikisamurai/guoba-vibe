# 字符已经正确，JSON 为什么还是解析失败？

## 第一步：复现拆行和 CRLF

```bash
pnpm --filter stream-render-lab practice test sse
```

在 <LabLink path="/project?source=mine">我的 Mini Chat</LabLink> 运行当前实现验收，检查 CRLF 跨切分、注释和多行 data 用例。初始实现的简单分隔无法覆盖这些边界。再到 <LabLink path="/playground?demo=network-inspector&source=mine">网络观察器</LabLink> 查看真实读取中是否出现半行或多条事件。

网络 chunk 结束不等于 SSE event 结束。不要对每次 decode 的结果直接 JSON.parse，也不要用 split('data:')。

## 第二步：先区分行与事件

```text
data: {"message":"hello"}

```

`data:` 是字段名；冒号后可去掉一个可选空格。空行结束一个事件。多条 data 行用换行拼接；以冒号开头的行是注释，不能混进 JSON。

SSE 支持 LF、CRLF 和 CR 行结束。一个 chunk 可能恰好停在 CR 与 LF 之间，解析器要保留跨片段状态。

## 第三步：修改自己的解析器

在 `parse-events.ts` 按下面顺序处理，保持当前接口不变：

1. 拼接上次未结束的行与新文本，逐行消费；留下半行。
2. 处理注释和字段；为当前事件累积 data。
3. 遇到空行时，按规则派发事件并重置事件状态。
4. EOF 不补造一个不存在的空行；未完整派发的事件不能冒充成功数据。

先让拆行测试通过，再处理换行形式、注释、多 data 行和一个 chunk 多事件。每次只修一类边界。

## 第五步：跑自己的验收

```bash
pnpm --filter stream-render-lab practice test sse
pnpm --filter stream-render-lab practice test sse --reference
```

预期：改变字节与文本切分不改变最终派发的事件序列；注释不会生成正文；缺失空行不会被当成完整事件。

SSE 的 event / id / retry 是协议字段；模型 JSON 里的 choices 是下一层。一个完整 SSE event 也可能只携带角色、用量或结束信息，不一定有字可显示。
