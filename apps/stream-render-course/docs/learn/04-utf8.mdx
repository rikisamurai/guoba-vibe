## 先复现乱码

```bash
pnpm --filter stream-render-lab lesson 04 test
```

预期失败：

```text
× decodes UTF-8 across arbitrary byte splits
Expected: "你好，👋 streaming"
Received: "������������� streaming"
```

错误实现为每个 chunk 新建 decoder：

```ts
chunks.map((chunk) => new TextDecoder().decode(chunk)).join('')
```

`你` 是 `E4 BD A0`，`🙂` 是 `F0 9F 99 82`。如果 chunk 只含 `E4 BD`，独立 decoder 不知道下一个 byte 还会来，只能输出 replacement character。

## 最小原理：decoder 自己也有跨 chunk 状态

```text
chunk A: E4 BD       decoder 暂存，不输出“你”
chunk B: A0 F0 9F    输出“你”，暂存 emoji 前半
chunk C: 99 82       输出“🙂”
EOF                  flush decoder
```

同一个 `TextDecoder` 必须贯穿一次 response；中间使用 `{ stream: true }`，EOF 再无参数 `decode()` 完成 flush。

## Checkpoint：任意切法都成立

- [ ] every-byte split 与整块输入得到同一 string。
- [ ] 中文、emoji 和 ASCII 混合 fixture 中没有 `�`。
- [ ] EOF 会 flush decoder 内部仍可完成的字符。

**Invariant：** `decode(partition(bytes)) === decode([bytes])`，对任何 chunk partition 都成立。

**Trade-off：** decoder 必须按 response 隔离并持有少量状态；换来 transport chunk 完全透明。

**退化条件：** 全 ASCII 输入看不出错误，因为每字符只有一个 byte；因此它不是有效的边界 fixture。

## 常见错误

- 每个 chunk 都 `new TextDecoder()`：多 byte 字符被破坏。
- 忘记 `{ stream: true }`：decoder 把每块当 EOF。
- 忘记最后 `decode()`：末尾暂存状态没有 flush。
- 把 byte offset 当 JavaScript string offset：后续 source range 会错位。

## 挑战题

枚举 `你好🙂` 编码后的每一个单 byte 切点，并证明结果一致。然后加入一个真正截断的末尾字符，记录 decoder 的替换行为；不要把“网络切片”与“响应截断”混为一谈。
