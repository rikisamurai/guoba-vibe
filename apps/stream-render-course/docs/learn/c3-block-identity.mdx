# 尾段在增长，前面的段落真的没变吗？

React 靠引用是否相同决定要不要重新渲染一个块。每帧全文解析都会产出一批全新的对象，内容没变，引用也变了。块复用是在解析之后做一次比对：这一块和上一帧同位置的块是不是同一个东西？是，就把旧对象递回去。难点在“同一个东西”的定义：原文相同只是必要条件。

**修改文件：** `src/my-chat/reuse-blocks.ts`。**集成配置：** `src/my-chat/render-policy.ts` 保持 M2。**算法入口：** `src/markdown/preview.ts` 的 reuseStableBlocks。下面路径相对 `apps/stream-render-lab/`。

## 第一步：观察不必要的前缀更新

在 <LabLink path="/lab">渲染实验台</LabLink> 用三段文字对比 M1、M2。尾段增长时检查前缀 blocks 的引用与渲染工作。

本课不复习 memo 的语法，而是问它需要什么输入契约：哪些节点可以保持引用，哪些看似相同但语义已经变化？

## 第二步：自己写出复用判断

```bash
pnpm --filter stream-render-lab practice test reuse
```

起点的 `reuseBlocks` 只比较 raw：原文相同，就交回上一帧的对象。验收给了两个它会放错的输入：引用链接的原文没变，但后到的定义让它从纯文本变成了链接；同样的原文出现在了不同的起点。

补齐条件：同位次、原文相同、起点相同、解析出的 node 也相同，才返回 `previous[index]`，否则返回新块。node 是普通对象，比较序列化后的文本即可。这个练习由验收单独运行，不接入 Mini Chat 的显示。

## 第三步：给引用复用一个反例

先写引用链接，后追加定义；或者在末尾追加 Setext 标题下划线。后续字符可能重新解释前面的结构。

打开 `reuseStableBlocks`，和自己刚写的判断对照：它多比较了块类型和区间终点，思路相同。只比较 raw 字符串会漏掉后到定义带来的含义变化。

## 第四步：检查 React 的另一半契约

打开 `src/rendering/render-document.tsx` 的 BlockView。它除了节点引用，还需要考虑终态与重型渲染结果。

如果最终高亮或图表没有出现，不能只因为 raw 没变就跳过渲染。引用稳定是减少工作的手段，语义正确才是约束。

## 第五步：让反例进入测试

在 `src/markdown/markdown.test.ts` 找到 keeps unchanged block identity 与相关语义回退用例，添加一个你关心的后到结构。分别断言：无变化前缀保持引用；受影响的块得到正确新语义。

```bash
pnpm --filter stream-render-lab exec vitest run src/markdown/markdown.test.ts src/rendering/render-document.test.tsx
```

预期不能用“所有块引用不变”作为成功标准，应该只复用真正不变的部分。

## 第六步：分开报告两种工作

在 <LabLink path="/profiler">性能实验</LabLink> 使用“大量独立段落”语料，对比 M1 与当前“我的实现”。检查 React commit / 渲染耗时与累计解析字符量。

M2 仍可能全文解析，所以“复用了块”不等于“解析变成线性”。下一课才进一步减少重复处理的输入。
